**Actionable findings in the integrated branch**

P1 means fix before relying on the affected build/release path. P2 means a concrete reliability, behavior, rendering or packaging issue that should be resolved before production. Confidence and evidence are stated for each finding.

1. **P1 — The integrated lab's advertised macOS preview does not compile.** [player.c:184](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/src/app/player.c:184), also line 185.

   The new `player_set_profile` takes `const char *` arguments and passes them to the pinned SDK's `cstr_copy(char *, char *, u32)`. The macOS toolchain treats the discarded qualifier as an error. `hz/hzbuild macos` exits 1 with two `-Wincompatible-pointer-types-discards-qualifiers` errors. This blocks the documented fast desktop validation loop for this lab. The separate original `player/` builds successfully, and the iOS framework compiles: this is a macOS regression, not evidence that iOS compilation fails.

   Fix the app boundary/copy operation using the pinned API's actual contract without disabling diagnostics or editing the shared SDK. A fixed POD profile can be passed/copied as such, or the app can use a suitable existing bounded string operation. Validate both native targets. Evidence: [lab-macos-build.log](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/out/code-audit-2026-10-19/lab-macos-build.log).

2. **P1 — Selecting Release builds the Swift host in Release but still builds the C application framework in Debug.** [build-engine.sh:10](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/build-engine.sh:10), [run.sh:154](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app_swift/run.sh:154), [run.sh:165](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app_swift/run.sh:165).

   `--configuration Release` changes `CONFIG` for `xcodebuild`; the engine script unconditionally runs `hz/hzbuild ios --framework` without `--release` and does not read that configuration. The build log confirms `ios-framework target (debug)`. The SDK core archive itself is precompiled release; the mismatch concerns the app-owned C modules/framework configuration. Calling the host build Release therefore does not establish a consistent release build or release performance.

   Pass the intended configuration through the framework build, stamp the resulting artifact with its engine/source/configuration identity, and reject `--skip-engine` reuse when that identity differs. Test a Release build from an empty app build-output directory. Evidence: [ios-host-source-build.log](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/out/code-audit-2026-10-19/ios-host-source-build.log).

3. **P2 — Queue pressure silently drops essential host state updates.** [app_host.c:31](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/src/app_swift/app_host.c:31), [HZEngine.swift:29](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app_swift/Sources/HZEngine.swift:29).

   All commands share a 32-slot ring. Once full, `engine_recv` silently returns, with no result or retry mechanism. A queue full of camera events can discard `SetActivity`, `SetCompanionProfile` or `SetCardsLayout`. Those values are otherwise resent on specific changes, so a dropped name clear, Reduce Motion change or visibility update can remain unapplied. SPSC ordering is reasonable; loss of critical state is the issue.

   Reproduced with the original ring implementation and dependency shims: enqueue 32 orbit commands, then `SetActivity(0)`, then drain. All 32 camera commands arrive; the activity command does not. A later retry succeeds. This is a bounded backpressure reproduction, not a claim that normal device use always fills the ring. See [ring-overflow-repro.c](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/out/code-audit-2026-10-19/ring-overflow-repro.c).

   Use reliable delivery or coalesced latest-value mailboxes for settings, and preserve lifecycle edges separately. Aggregate camera deltas or make their loss policy explicit. Report overflow in debug builds. Do not enlarge the ring and assume the delivery contract is fixed.

4. **P2 — A suspension/resumption pair can bypass the required fresh quiet interval.** [player.c:189](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/src/app/player.c:189), [player.c:993](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/src/app/player.c:993), [calm_life.c:82](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/src/app/calm_life.c:82).

   `player_set_activity` only overwrites a level. `CalmLife.quiet` resets when a simulation tick actually observes `suspended`. If inactive and active commands are both processed before the next intent tick—for example when commands accumulate while rendering is suspended—both can be delivered correctly yet the intent system sees only the final active level. The old quiet timer or walk state survives. The next tick can start/resume walking immediately, contrary to the fresh quiet interval specified in the lab instructions.

   This is a source-level interleaving finding; it was not reproduced on a physical phone in this review. Preserve an inactivity/resumption generation or sticky reset request at command dispatch and consume it before the next activity tick. Test a pause/resume sequence with no intervening engine tick, including a nearly expired quiet timer and an interrupted walk. This needs a separate fix from queue overflow.

5. **P2 — Foliage deformation and its shadow caster disagree.** [nature_wind.glsl:59](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/shaders/renderer/nature_wind.glsl:59), [Grass_mat.hzt:1](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app/assets/environments/quaternius/materials/Grass_mat.hzt:1).

   The color vertex shader displaces foliage using wind metadata and time. The foliage materials have `passes 0`; the pinned `MaterialBlobAsset` header explicitly defines an empty pass list as the global shadow fallback. That fallback computes static world positions and contains no matching wind deformation. The scene and submeshes cast shadows, so the visible plant can sway away from its static shadow.

   Factor the deformation into a project-local shared shader include and apply it in a material-compatible shadow pass. Keep the shadow pass on the pinned SDK's actual `passes`/`RENDERER_PHASE_SHADOW` contract; do not rely on an older wiki reference to a legacy field. If adding a depth prepass or temporal upscaling later, its depth and previous-frame motion paths must also match the deformation. The present mismatch is established from shader/material/header contracts; no new rendered comparison was possible for the latest lab macOS source because of finding 1.

6. **P2 — The screenshot automation can return success after a failed UI test.** [shot.sh:95](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app_swift/shot.sh:95), [shot.sh:119](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app_swift/shot.sh:119).

   The script captures `TEST_RC`, prints it, then runs screenshot extraction without returning that status. If extraction fails, its final `echo` succeeds; with successful extraction, listing the screenshots can also succeed after tests failed. An automated caller can therefore record a passing verification step after `xcodebuild test` returned 65.

   Reproduced by running the unmodified extraction tail with `TEST_RC=65` and a failing export: shell exit status was 0. See [shot-exit-repro.sh](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/out/code-audit-2026-10-19/shot-exit-repro.sh). Preserve useful attachments, then exit with the original test status; fail an otherwise successful requested capture when the expected image is missing. Check the same behavior with a real failed UI assertion.

7. **P2 — The native resource phase copies the complete development cook into the phone app.** [project.yml:19](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/app_swift/project.yml:19), [build-engine.sh:10](/Users/m0saan/.codex/.chatgpt-projects/g-p-6ad3e17bdc34819193b11d3075da4659/character-harness/ios/KloeyCompanionLab/build-engine.sh:10).

   The built device app contains 422,988,226 bytes, about **403.4 MiB**, in `cooked/` alone, across 1,261 files. Approximately 239.4 MiB under `engine/` is predominantly font atlas pages. The FoxGlove directory is about 127.7 MiB and includes both ASTC and desktop BC texture variants; the tree also contains multiple shader backends and inactive scene content. The Release host uses the same whole-folder resource rule.

   These are measured uncompressed development-bundle resources, not an App Store download estimate and not a resident-memory measurement. Introduce a target-specific shipping stage with the required asset dependency closure, supported compression and an asset budget. Validate loader dependencies rather than deleting arbitrary engine/font files, and never remove files from the shared SDK. Produce a thinned archive size report before claiming download savings. [Apple's app-size guidance](https://developer.apple.com/documentation/xcode/reducing-your-app-s-size) explains the appropriate measurement.

**What is already following the intended patterns**

- Runtime behavior is added as a generic optional context protocol plus a `world-context` extension. Character personality, scene descriptions, capabilities, thought threads and reminders live in character configuration rather than character-specific branches in `runtime/`.
- Snapshot validation reconstructs an allowlist, bounds numeric/string/array input, recognizes scene/avatar identifiers, and removes current scene facts after five seconds. Turn snapshots and retained profiles are isolated per connection. Name removal is explicit.
- The profile bridge pins the 226-byte C payload and Swift's 230-byte tagged message, NUL-terminates on dispatch, validates Unicode names, and uses JSON escaping for the strings. Main-queue profile notifications honor the single UI-thread producer contract.
- Locomotion uses the gameplay-blocks controller, fixed steps/interpolation, ECS component state and a read-only input resource, engine RNG/damping and temporary pose allocations. Voice priority is wired into the activity state. The bounded flat corridor is deliberate and its exported geometry validator passes; absence of free-world navigation is not itself a bug.
- The fixed-step helper is explicitly designed to be called by every lane; its accumulators are replicated per thread. I did not treat that call as a shared-state race.
- The host ring's file-scope storage is the documented host-boundary exception. I did not report it as an arbitrary forbidden gameplay global.
- Provider keys stay server-side, saved development connection settings use Keychain, explicit preview overrides are preserved, and transcript tracing is disabled by default. The changed-text credential-shape scan found no matching embedded provider key or KGEN key. This scan is supplementary, not a complete secrets audit.

**Production gaps and maintenance work**

A green runtime suite is insufficient release evidence.
- Make connection, listening, thinking, playback and error state visible in the host. Supply a real mute/stop control, permission-denied recovery and reconnect behavior. Currently `SetActivity` controls wandering, while the microphone tick enables voice from the sticky `mic_running` flag; it is not an explicit conversation lifecycle policy. Verify SDK-owned audio behavior before adding a second audio-session owner. Use the existing `character_voice_set_active` cancellation path where appropriate, and handle audio interruption/resumption and route changes at an agreed host/engine boundary. The specific audio failure behavior remains a device validation gap. - The shared development bearer URL over LAN `ws://` is appropriate to the documented lab setup, but is not a production user/session service. Shipping needs authenticated user-scoped sessions, encrypted transport, token expiry/rotation and resource limits, while provider credentials remain on the server. The optional display name must not become authorization identity.
- Consolidate duplicated player code and assets through a shared project-owned module or reproducible synchronization step. `app_character`, `player_json`, `player_vrm` and related files currently match the desktop copies; manually maintaining both will make future fixes easy to miss. - Remove unused UI scaffolding (`intentionCard`, unreachable intentions sheet, placeholder `SceneBackground`, empty Tasks action, commented layout line), or wire it to real behavior. The card actions currently open detail screens; “Start chat” does not submit a harness turn. Treat this as unfinished product integration, not a working conversation feature.
- Remove the unused duplicate `characters/foxglove/animations/director.yaml` or generate it from the manifest-selected file. Update old `XAI_API_KEY` setup instructions to the current manifest. These are configuration/documentation drift, not native crashes.
- The prompt evaluation records known formatting/question-pacing lapses. Preserve its distinction between generated text, requested speech and verified playback. Run a targeted spoken device evaluation before claiming those problems are solved; I did not rerun the paid comparison.
